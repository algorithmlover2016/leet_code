# 算法详解：检查操作后字符串中的数字是否相等 II

该算法解决的问题是：给定一个数字字符串，每次将相邻两个数字相加取个位产生新的字符串，重复此过程直到只剩两个数字，判断这两个数字是否相等。

这是一个基于**组合数学**和**数论**的高效解法。与其直接模拟 $O(N^2)$ 的归约过程，该算法利用了帕斯卡三角形的性质，将时间复杂度降低到了 $O(N \log N)$ 级别。

## 1. 核心思想：帕斯卡三角形 (Pascal's Triangle)

这种“相邻数字相加”的操作本质上是在计算帕斯卡三角形的顶端。

### 为什么系数是二项式系数？(证明与直观解释)

让我们通过一个小例子来观察系数是如何变化的。
假设我们有一个数字序列 $d_0, d_1, d_2, d_3$。我们想知道经过 3 次操作将其合并成 1 个数字时，初始的每个数字贡献了多少次。

*   **初始状态** (第 0 层):
    $d_0, d_1, d_2, d_3$

*   **第 1 次操作** (第 1 层):
    $(d_0 + d_1), (d_1 + d_2), (d_2 + d_3)$

*   **第 2 次操作** (第 2 层):
    将第 1 层的相邻项相加：
    $val_1 = (d_0 + d_1) + (d_1 + d_2) = 1\cdot d_0 + 2\cdot d_1 + 1\cdot d_2$
    $val_2 = (d_1 + d_2) + (d_2 + d_3) = 1\cdot d_1 + 2\cdot d_2 + 1\cdot d_3$
    *(注意系数：1, 2, 1，对应帕斯卡三角形第 2 行)*

*   **第 3 次操作** (第 3 层，最终结果):
    $Final = val_1 + val_2$
    $Final = (1\cdot d_0 + 2\cdot d_1 + 1\cdot d_2) + (1\cdot d_1 + 2\cdot d_2 + 1\cdot d_3)$
    $Final = 1\cdot d_0 + 3\cdot d_1 + 3\cdot d_2 + 1\cdot d_3$
    *(注意系数：1, 3, 3, 1，对应帕斯卡三角形第 3 行)*

**结论**：
如果我们要进行 $m$ 次操作，原始序列中第 $i$ 个位置（从 0 开始）的数字，最终会被加 $\binom{m}{i}$ 次。
因此，我们可以直接用公式计算最终结果，而不需要逐层模拟。

---

如果原始字符串长度为 $n$，为了剩下最后 2 个数字，我们需要进行 $m = n - 2$ 轮操作。

*   **左边的最终数字** ($Left$)：由原始字符串索引 $0$ 到 $m$ 的数字贡献而成。
    $$ Left = \sum_{i=0}^{m} \binom{m}{i} \times s[i] \pmod{10} $$
*   **右边的最终数字** ($Right$)：由原始字符串索引 $1$ 到 $m+1$ 的数字贡献而成。
    $$ Right = \sum_{i=0}^{m} \binom{m}{i} \times s[i+1] \pmod{10} $$

关键难点在于：当 $n$ 很大时，直接计算组合数会溢出，我们需要计算的是 $\binom{n}{k} \pmod{10}$。

## 2. 数学原理：模 10 的组合数计算

由于 10 不是质数，我们不能直接应用卢卡斯定理（Lucas' Theorem）。但由于 $10 = 2 \times 5$，且 2 和 5 互质，我们可以使用 **中国剩余定理 (Chinese Remainder Theorem, CRT)** 将问题分解。

我们需要分别计算：
1.  MOD 2 的结果
2.  MOD 5 的结果

### 2.1 计算 $\binom{n}{k} \pmod 2$

根据卢卡斯定理的推论，$\binom{n}{k}$ 是奇数（即 $\equiv 1 \pmod 2$）当且仅当二进制下 $k$ 的每一位 1 都在 $n$ 的对应位上也是 1。
这可以通过位运算极快地判断：
```cpp
// 如果 (n & k) == k，说明 k 的所有二进制 1 都是 n 的子集
int nCrMod2(int n, int k) {
    return ((n & k) == k) ? 1 : 0;
}
```

### 2.2 计算 $\binom{n}{k} \pmod 5$

5 是质数，可以直接使用 **卢卡斯定理**。
公式为：
$$ \binom{n}{k} \equiv \binom{n/5}{k/5} \times \binom{n \pmod 5}{k \pmod 5} \pmod 5 $$
代码中 `lucasMod5` 函数递归地实现了这一点，并配合预计算的小范围组合数表 `C_MOD_5` 加速计算。

### 2.3 深入解析：为什么公式是 (5 * mod2 + 6 * mod5)？

代码中有这样一行：
```cpp
return (5 * mod2 + 6 * mod5) % 10;
```
这是 **中国剩余定理 (CRT)** 的构造性解法。

**核心问题：为什么非要找这样的 $K_1$ 和 $K_2$？**

你想想，我们的目标是合成一个数 $x$，它由两部分组成：`mod2` 的部分和 `mod5` 的部分。
$$ x = K_1 \times \text{mod2} + K_2 \times \text{mod5} $$

我们希望实现**“互不干扰” (解耦)**：
1.  当我们改变 `mod2` 的值时，$x$ 对 5 取模的结果**不能变**。
    *   怎么做到？最好的办法就是让 $K_1 \times \text{mod2}$ 这一项是 5 的倍数。这样无论怎么加，除以 5 的余数都是 0，不会干扰另一边。
    *   所以 **$K_1$ 必须是 5 的倍数**。

2.  同理，当我们改变 `mod5` 的值时，$x$ 对 2 取模的结果**不能变**。
    *   怎么做到？最好的办法就是让 $K_2 \times \text{mod5}$ 这一项是 2 的倍数。
    *   所以 **$K_2$ 必须是 2 的倍数**。

这就是为什么我们要找这样的系数：
*   $K_1 = 5$：它是 5 的倍数（不干扰 mod 5），且模 2 余 1（完美传递 mod 2 的值）。
*   $K_2 = 6$：它是 2 的倍数（不干扰 mod 2），且模 5 余 1（完美传递 mod 5 的值）。

这就好比调节音响的 **“左右声道”**。$K_1$ 是左声道开关，$K_2$ 是右声道开关。
*   $K_1$ (数字 5) 的特性是：在“模 5 世界”里是静音的 (余 0)，但在“模 2 世界”里是最大声的 (余 1)。
*   $K_2$ (数字 6) 的特性是：在“模 2 世界”里是静音的 (余 0)，但在“模 5 世界”里是最大声的 (余 1)。

只有这样，我们才能把两个独立计算出来的余数 $a$ 和 $b$，无损地合并成一个最终结果。

## 3. 代码逻辑流程

函数 `hasSameDigits`:
1.  **特判**：如果 $n=2$，直接比较两个字符。
2.  **设定目标**：需要归约的次数 $m = n - 2$。
3.  **线性组合求和**：
    *   遍历 $i$ 从 $0$ 到 $m$。
    *   计算组合数系数 `coeff` = $\binom{m}{i} \pmod{10}$。
    *   累加到 `leftSum`：$s[i] \times \text{coeff}$。
    *   累加到 `rightSum`：$s[i+1] \times \text{coeff}$。
4.  **返回结果**：比较 `leftSum` 和 `rightSum` 是否相等。

## 4. 复杂度分析

*   **时间复杂度**: $O(N \log N)$
    *   我们需要遍历 $N$ 个位置。
    *   对于每个位置，计算 `lucasMod5` 需要 $O(\log_5 N)$ 的时间。
    *   总时间复杂度为 $O(N \log N)$，这比直接模拟的 $O(N^2)$ 快得多。
*   **空间复杂度**: $O(1)$
    *   只需要常数级的额外空间用于存储查找表和变量。
